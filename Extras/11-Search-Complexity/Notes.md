# Search Complexity

## 1. Introduction

Search algorithms find a required element, state, node, or solution from a collection or search space.

Important measures:

- **Time complexity:** how running time grows with input size.
- **Space complexity:** how memory requirements grow.
- **Completeness:** whether a solution is guaranteed to be found when one exists.
- **Optimality:** whether the best/lowest-cost solution is guaranteed.

AI search spaces can become extremely large, so complexity is important.

## 2. Big-O Notation

Big-O describes the growth rate of an algorithm.

Common complexities:

- O(1) — constant
- O(log n) — logarithmic
- O(n) — linear
- O(n log n) — linearithmic
- O(n²) — quadratic
- O(2ⁿ) — exponential
- O(n!) — factorial

Slower-growing complexity generally scales better as n increases.

## 3. Linear Search

Linear Search checks elements sequentially.

Example:

[10, 20, 30, 40, 50]

To find 40:

10 → 20 → 30 → 40

Time:

- Best case: O(1)
- Average case: O(n)
- Worst case: O(n)

Auxiliary space:

- O(1)

## 4. Binary Search

Binary Search works on a **sorted** array.

Process:

1. Find the middle element.
2. Compare it with the target.
3. If equal, return it.
4. If target is smaller, search the left half.
5. If target is larger, search the right half.
6. Repeat.

Time:

- Best case: O(1)
- Average case: O(log n)
- Worst case: O(log n)

Space:

- Iterative: O(1)
- Recursive: O(log n)

### Linear vs Binary Search

| Feature | Linear | Binary |
|---|---|---|
| Sorting required | No | Yes |
| Best | O(1) | O(1) |
| Average | O(n) | O(log n) |
| Worst | O(n) | O(log n) |
| Auxiliary space | O(1) | O(1) iterative |

## 5. Tree Terminology

Important terms:

- Root — starting/top node.
- Parent — node directly above another node.
- Child — node directly below another node.
- Leaf — node with no children.
- Depth — distance from root.
- Height — maximum depth.
- Branching factor b — number of children generated by a node.
- Solution depth d — depth of the shallowest solution.
- Maximum depth m — deepest level considered.

## 6. Breadth-First Search (BFS)

BFS explores level by level.

It uses a **queue**.

Queue:

- FIFO — First In, First Out.

Example:

        A
       / \
      B   C
     / \   \
    D   E   F

BFS:

A → B → C → D → E → F

### BFS Complexity

For a graph:

- Time: O(V + E)
- Space: O(V)

For a tree/search tree:

- Time: O(b^d)
- Space: O(b^d)

BFS can require a lot of memory because it stores a large frontier.

### Properties

- Complete under standard finite-branching assumptions.
- Optimal for equal-cost/unweighted paths.
- High memory requirement.

## 7. Depth-First Search (DFS)

DFS explores one branch deeply before backtracking.

It uses:

- Stack
- Recursion

Stack:

- LIFO — Last In, First Out.

Example DFS order:

A → B → D → E → C → F

The exact order depends on child ordering.

### DFS Complexity

For a graph:

- Time: O(V + E)
- Space: O(V)

For a tree/search tree:

- Time: O(b^m)
- Space: O(bm)

### Properties

- Usually uses less memory than BFS.
- Not generally optimal.
- Not always complete in infinite-depth spaces.
- Useful for deep exploration and backtracking.

## 8. BFS vs DFS

| Feature | BFS | DFS |
|---|---|---|
| Data structure | Queue | Stack/recursion |
| Search order | Level-by-level | Deep-first |
| Complete | Yes under standard assumptions | Not always |
| Optimal | Equal-cost paths | No |
| Tree time | O(b^d) | O(b^m) |
| Tree space | O(b^d) | O(bm) |
| Memory | High | Lower |

Here:

- b = branching factor
- d = shallowest solution depth
- m = maximum search depth

## 9. Graph Search and Visited Sets

Graphs may contain cycles.

Example:

A → B → C
↑       ↓
└───────┘

Without a visited set, the algorithm may repeatedly explore the same nodes.

A graph-search algorithm commonly maintains:

visited = set()

Process:

1. Check whether a node has been visited.
2. If already visited, skip it.
3. Otherwise mark it visited.
4. Expand its neighbours.

This prevents repeated exploration and infinite loops in cyclic graphs.

## 10. Uniform-Cost Search (UCS)

UCS expands the node with the smallest path cost.

It uses a priority queue.

The evaluation is:

g(n)

where g(n) is the actual cost from the start node to n.

UCS is useful when different actions have different costs.

With standard non-negative-cost assumptions, UCS is complete and optimal.

It can require substantial time and memory.

## 11. Greedy Best-First Search

Greedy Best-First Search chooses the node that appears closest to the goal.

It uses:

h(n)

where h(n) estimates the remaining cost to the goal.

Evaluation:

h(n)

Advantages:

- Can be fast with a good heuristic.

Limitations:

- Ignores cost already travelled.
- Not generally optimal.

## 12. A* Search

A* combines actual cost and estimated remaining cost.

Formula:

f(n) = g(n) + h(n)

Where:

- g(n) = actual cost from start to n.
- h(n) = estimated cost from n to goal.
- f(n) = estimated total cost through n.

A* expands the node with the smallest f(n).

It combines the ideas of UCS and heuristic search.

With an appropriate heuristic and standard assumptions, A* can be optimal.

## 13. 8-Puzzle and Manhattan Distance

For the 8-puzzle, Manhattan distance can be used as a heuristic.

For each tile:

Manhattan distance =
|current row - goal row| +
|current column - goal column|

Total heuristic:

h(n) = sum of the Manhattan distances of all tiles.

The blank tile is normally excluded.

## 14. Admissible Heuristic

A heuristic is **admissible** if it never overestimates the true remaining cost.

Formula:

h(n) ≤ h*(n)

Where:

- h(n) = estimated remaining cost.
- h*(n) = actual minimum remaining cost.

An admissible heuristic is optimistic.

For standard A* tree search, admissibility supports optimality under the relevant assumptions.

## 15. Consistent Heuristic

A heuristic is consistent if:

h(n) ≤ c(n,n') + h(n')

Where:

- c(n,n') = cost from n to n'.
- h(n) = heuristic at n.
- h(n') = heuristic at n'.

Consistency implies admissibility under standard conditions.

It also makes graph-search A* easier to manage because f-values do not decrease along a path.

## 16. Search Complexity Using b and d

Let:

- b = branching factor
- d = shallowest solution depth
- m = maximum depth

### BFS

Time:

O(b^d)

Space:

O(b^d)

### DFS

Time:

O(b^m)

Space:

O(bm)

Example:

If b = 10 and d = 6:

10^6 = 1,000,000

The search space can therefore grow extremely quickly.

## 17. Complexity of Common Search Algorithms

| Algorithm | Criterion | Typical Time | Typical Space | Optimal? |
|---|---|---|---|---|
| Linear Search | Sequential | O(n) | O(1) | N/A |
| Binary Search | Middle/division | O(log n) | O(1) iterative | N/A |
| BFS | Smallest depth | O(b^d) | O(b^d) | Equal-cost paths |
| DFS | Deepest available | O(b^m) | O(bm) | No |
| UCS | Lowest g(n) | Depends on costs | High | Yes under standard conditions |
| Greedy Best-First | Lowest h(n) | Can be exponential | High | No |
| A* | Lowest g(n)+h(n) | Depends on heuristic | High | Yes with suitable conditions |

Exact complexity for UCS, Greedy Best-First, and A* depends on the search space, branching factor, costs, and heuristic.

## 18. Tree Traversals

For a tree containing n nodes:

### Preorder

Root → Left → Right

Time:

O(n)

### Inorder

Left → Root → Right

Time:

O(n)

### Postorder

Left → Right → Root

Time:

O(n)

### BFS Tree Traversal

Uses a queue.

Time:

O(n)

Space:

O(w)

where w is maximum tree width.

### DFS Tree Traversal

Time:

O(n)

Recursive auxiliary space:

O(h)

where h is tree height.

## 19. Binary Search Tree and Inorder

For a Binary Search Tree, inorder traversal produces sorted values.

Example:

        5
       / \
      3   7
     / \ / \
    2  4 6  8

Inorder:

2 → 3 → 4 → 5 → 6 → 7 → 8

## 20. Choosing an Algorithm

### Linear Search

Use when:

- Data is unsorted.
- Dataset is small.
- Simplicity is important.

### Binary Search

Use when:

- Data is sorted.
- Fast lookup is required.

### BFS

Use when:

- Solution is likely shallow.
- Shortest path in an unweighted graph is required.

### DFS

Use when:

- Memory is limited.
- Deep exploration is useful.
- Backtracking is required.

### UCS

Use when:

- Path costs differ.
- Lowest-cost solution is required.

### Greedy Best-First

Use when:

- A useful heuristic exists.
- Fast heuristic-guided exploration is preferred.

### A*

Use when:

- Path cost matters.
- A useful heuristic exists.
- Optimality is required under suitable conditions.

## 21. Common Mistakes

1. Using binary search on unsorted data.
2. Confusing BFS queue with DFS stack.
3. Forgetting BFS memory requirements.
4. Saying DFS always finds the shortest path.
5. Forgetting visited sets in cyclic graphs.
6. Confusing g(n) and h(n).
7. Writing A* as h(n) instead of g(n)+h(n).
8. Assuming every heuristic is admissible.
9. Confusing tree-search and graph-search complexity.
10. Forgetting that complete tree traversal is O(n).

## 23. Exam Summary

- Linear Search checks elements sequentially.
- Binary Search repeatedly halves a sorted search space.
- BFS uses a queue and searches level by level.
- DFS uses a stack/recursion and explores deeply before backtracking.
- Graph search should track visited states when cycles are possible.
- UCS chooses the smallest g(n).
- Greedy Best-First chooses the smallest h(n).
- A* chooses the smallest f(n)=g(n)+h(n).
- An admissible heuristic never overestimates the true remaining cost.
- A consistent heuristic satisfies the consistency inequality.
- BFS is optimal for equal-cost paths but can require large memory.
- DFS generally uses less memory but is not optimal.
- Tree traversals take O(n) time.
- Search spaces can grow exponentially with branching factor and depth.
